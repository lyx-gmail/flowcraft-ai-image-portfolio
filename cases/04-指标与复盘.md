# 案例四：指标、验收口径与复盘

## 交付与指标

- 成品：10 款商品 ×（1 主图 + 3 详情 + 1 广告）= **50 张**，全部标准 1K；主图 1024×1024，详情与广告 1152×1536。
- 提交纪律：**50/50 单次提交、零自动重试**；每张图都有请求记录（编号、耗时、状态），49 份后台回执全部为「已验收」，无重复操作编号。
- 耗时（后台 49 次，秒）：请求整体 28.3 / 33.0 / 40.2（最小 / 中位 / 最大）；其中上游渲染 24.9 / 29.7 / 36.3。JBL 主图经网页工作台完成，请求 32.3 秒、上游 30.6 秒，与后台数据一致。
- 额度：访客每个 IP 每天 5 张、全站每天 100 张、分析调用 40 次/天，管理员白名单不受限——让新用户能真实体验，同时把被滥用的成本上限写死在产品里。

## 验收口径

每张图都按同一张清单逐张人工验收，公开仓库提供[验收摘要](../records/合格成品清单.md)，原始回执与规划在本地归档：

1. **商品身份**：型号、颜色、容量、接口、数量与商品原图一致（不出现「Flip 6」「16oz」「白色 OM7」这类串款）。
2. **文字边界**：新增文案只用已确认的中文标题与卖点；包装原有英文、容量、印章按原图保留，不翻译、不外扩为认证或医疗承诺（完整清单见 `records/商品卖点.md`）。
3. **构图**：一张图只讲一件事，禁止多联拼图；详情三张分别为概览、细节、场景。
4. **小字复核**：对镜头铭文与包装小字做放大抽查（例如镜头的 LEICA 铭文、Aveeno 的 48hr、Vaseline 的 72HR MOISTURE 均为原包装文字，不是我们新增的功效承诺）。

## 复盘：如果继续做

- 质量前移：把「一图一场景、禁止拼图、文字边界」做成提交前的硬校验，让不合格在付费前被拦住（[案例二](02-详情图规划修复.md)已经完成第一步）。
- 验收半自动化：用 OCR 抽查文案与小字，把人工从「逐字看」降到「看告警与抽样」。
- 商业化：面向小卖家的按张包 / 按月订阅、面向代运营的批量席位，核心差异不是模型，而是商品一致性与合规边界的可控性。
- 能力补齐：2K 精细档已在产品里可用；下一步是模板化的类目预设（不同平台的尺寸、文字区、常见卖点结构）。

一句话总结这 50 张图对我意味着什么：**它们不是一次生图展示，而是一条「定义标准 → 生产 → 验收 → 发现问题 → 修复并锁死」的产品闭环的可复核证据。**
